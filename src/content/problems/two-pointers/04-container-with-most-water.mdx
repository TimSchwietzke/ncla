<Statement>

You are given an array `height` of length `n`, describing `n` vertical lines where line `i` runs from
`(i, 0)` to `(i, height[i])`. Two lines and the x-axis form a container. Return the **most water**
such a container can hold. The container may not be slanted.

The water a pair holds is `min(height[left], height[right]) * (right - left)` — the shorter wall sets
the level, the distance sets the width.

<Examples>
  <Example input={`height = [1, 8, 6, 2, 5, 4, 8, 3, 7]`} output="49">
    Lines at index 1 and index 8: `min(8, 7) * (8 - 1) = 7 * 7 = 49`.
  </Example>
  <Example input={`height = [1, 1]`} output="1">
    Two walls of height 1, one apart.
  </Example>
  <Example input={`height = [1, 2, 4, 3]`} output="4">
    The widest pair holds `1 * 3 = 3`; indices 2 and 3 hold `3 * 1 = 3`; indices 1 and 3 win with
    `2 * 2 = 4`. Neither the widest nor the tallest pair is the answer.
  </Example>
</Examples>

<Constraints>

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`

</Constraints>

</Statement>

<Signals>

- The quantity depends on a **pair** and on the **distance between them**. Starting at maximum width
  and giving width away is the only way to make that trade visible.
- `n` up to `10^5` puts every pair at `5 · 10^9`. `O(n)` is required, so each step must eliminate a
  whole family of candidates, not just one.
- The value is capped by the **shorter** of the two walls, which means one of the two is provably
  useless. That asymmetry is the door in.

</Signals>

<BruteForce>

Compute the area for every pair and keep the maximum.

**O(n²) time, O(1) space.** The bottleneck is that it treats both walls as equally worth keeping.
When a pair fails, the pair that comes next is chosen arbitrarily — although the geometry already
says which of the two walls can never be part of a better container.

</BruteForce>

<Insight>

The shorter wall caps the water, and since moving inwards only ever loses width, keeping it can never pay off.

</Insight>

<Approach>

1. Put `left` at 0 and `right` at `n - 1` — the widest container there is.
2. Record `min(height[left], height[right]) * (right - left)`.
3. Move the pointer standing on the **shorter** wall one step inwards.
4. Repeat until the pointers meet, keeping the largest area seen.

Step 3 is the whole problem, and the argument for it is what an interviewer asks for. Pair the
shorter wall with anything else: the width can only shrink, and the water level is still capped by
that same short wall. So no container involving it can beat the one just measured — it can be
discarded outright. The taller wall carries no such guarantee, which is why it stays.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def maxArea(self, height: list[int]) -> int:
        # O(n^2) time, O(1) space
        best = 0
        for i in range(len(height)):
            for j in range(i + 1, len(height)):
                best = max(best, min(height[i], height[j]) * (j - i))
        return best
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def maxArea(self, height: list[int]) -> int:
        # O(n) time, O(1) space
        left, right = 0, len(height) - 1
        best = 0

        while left < right:
            best = max(best, min(height[left], height[right]) * (right - left))

            if height[left] < height[right]:
                left += 1                  # the short wall can never do better
            else:
                right -= 1

        return best
```

</Solution>

<Pitfalls>

- **The justification is the interview question, not the code.** Four lines are easy; "why is
  discarding the shorter wall safe?" is what is actually being marked. Practise it as one sentence:
  paired with anything else it gives less width and the same cap, so it cannot beat what was just
  measured.
- Measure **before** moving. Computing the area after advancing a pointer silently skips the widest
  container of all.
- On equal heights it does not matter which side moves — both are capped identically. Move either,
  but do move exactly one, or the loop never ends.
- Do not confuse this with Trapping Rain Water. Here two walls hold one body of water and everything
  between them is ignored; there, every position holds its own column and the bars in between matter.

</Pitfalls>

<FollowUps>

- *"Return the two indices, not just the amount."* — Store them alongside `best`. It costs nothing
  and it is a common follow-up.
- *"Prove the greedy is optimal."* — Every pair that includes the discarded wall has width no greater
  than the current one and a level no greater than that wall, so its area is bounded by the area just
  recorded. Discarding it removes no better answer, and induction finishes the argument.
- *"What if the container could be slanted?"* — Then the shorter wall no longer caps the level and
  the whole argument collapses; it becomes a geometry problem rather than a two-pointer one.

</FollowUps>
