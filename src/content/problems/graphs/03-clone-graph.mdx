<Statement>

Given a reference to a node in a **connected undirected** graph, return a **deep copy** of the whole
graph. Each node holds a value and a list of neighbours.

<Examples>
  <Example input={`adjList = [[2,4],[1,3],[2,4],[1,3]]`} output={`[[2,4],[1,3],[2,4],[1,3]]`}>
    A four-node cycle. Node 1 neighbours 2 and 4; the copy must have the same shape with new nodes.
  </Example>
  <Example input={`adjList = [[]]`} output={`[[]]`}>
    A single node with no neighbours.
  </Example>
  <Example input={`adjList = []`} output={`[]`}>
    An empty graph — the input reference is `null`.
  </Example>
</Examples>

<Constraints>

- `0 <= number of nodes <= 100`, `1 <= Node.val <= 100`, values are unique
- No repeated edges and no self-loops
- The graph is **connected**, so every node is reachable from the given one

</Constraints>

</Statement>

<Signals>

- Undirected edges mean every edge appears **twice**, so a naive traversal walks straight back where
  it came from. Something has to remember what has already been copied.
- That memory is a map from **original node to its copy**, which doubles as the visited set. One
  dictionary does both jobs, and noticing that is the solution.
- The graph has cycles, so a copy cannot be built bottom-up like a tree. A node's neighbour may be a
  node still being constructed higher up the call stack.

</Signals>

<BruteForce>

Collect every node in one pass, create all the copies, then wire the neighbours in a second pass.

**O(V + E) time, O(V) space.** This is genuinely correct and it is exactly the Copy List with Random
Pointer approach. It is not slower — it just walks the graph twice where once suffices, because the
map can be filled as the traversal goes.

</BruteForce>

<Insight>

Put a node's copy in the map before visiting its neighbours, and a cycle finds the copy already waiting for it.

</Insight>

<Approach>

1. Keep `copies`, a dictionary from original node to cloned node.
2. `clone(node)`: if it is already in `copies`, return the existing clone. This is both the
   memoisation and the cycle guard.
3. Otherwise create the clone with the same value and **register it immediately**, before recursing.
4. For each neighbour, append `clone(neighbour)` to the copy's neighbour list.
5. Return the clone.

Step 3's ordering is the whole trick. Registering before recursing means that when the recursion comes
back around the cycle, step 2 finds a clone that exists but whose neighbours are still being filled —
and that is fine, because the reference is what gets stored.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def cloneGraph(self, node: "Optional[Node]") -> "Optional[Node]":
        # O(V + E) time, O(V) space — two passes, like Copy List with Random Pointer
        if not node:
            return None

        # Pass 1: find every node.
        originals: list = []
        seen = {node}
        stack = [node]
        while stack:
            current = stack.pop()
            originals.append(current)
            for neighbour in current.neighbors:
                if neighbour not in seen:
                    seen.add(neighbour)
                    stack.append(neighbour)

        # Pass 2: create the copies, then wire them.
        copies = {original: Node(original.val) for original in originals}
        for original in originals:
            copies[original].neighbors = [copies[n] for n in original.neighbors]

        return copies[node]
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def cloneGraph(self, node: "Optional[Node]") -> "Optional[Node]":
        # O(V + E) time, O(V) space — one pass
        copies: dict = {}

        def clone(original):
            if original in copies:
                return copies[original]        # memo AND cycle guard

            copy = Node(original.val)
            copies[original] = copy            # register BEFORE recursing

            for neighbour in original.neighbors:
                copy.neighbors.append(clone(neighbour))

            return copy

        return clone(node) if node else None
```

</Solution>

<Pitfalls>

- **Register the copy before recursing into the neighbours.** Creating the clone, recursing, and only
  then storing it means a cycle re-enters the same node forever. This one line ordering is the whole
  problem.
- **Handle the null input.** An empty graph is a legal input and `clone(None)` would raise. The guard
  belongs at the call site, not inside the recursion.
- Key the map by the **node object**, not by `node.val`. The values happen to be unique here, which
  makes a value-keyed map work by accident — and it stops working the moment that guarantee is
  dropped.
- Every undirected edge is stored on both endpoints, so the copy's neighbour lists are built twice
  from opposite ends. That is correct and expected; a solution that tries to add each edge once ends
  up with half the adjacency.
- Depth is up to 100 here, so recursion is safe. On a larger graph an explicit stack with the same map
  is the same algorithm.

</Pitfalls>

<FollowUps>

- *"Do it iteratively."* — A queue or stack plus the same `copies` map: pop an original, and for each
  neighbour create its copy if absent, enqueue it, and append it to the current copy's list.
- *"A disconnected graph."* — The single reference no longer reaches everything. You would need the
  full node list, and the outer loop becomes "clone from every unvisited node".
- *"Why is this Copy List with Random Pointer again?"* — Both need a map from original to copy so that
  a pointer to a not-yet-built node resolves. The list version could split it into two clean passes;
  the cycles here make the register-first ordering the interesting part.

</FollowUps>
