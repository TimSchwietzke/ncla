<Statement>

Given `n` nodes labelled `0` to `n - 1` and a list of **undirected** edges, decide whether they form a
valid **tree** — connected and acyclic.

<Examples>
  <Example input={`n = 5
edges = [[0,1],[0,2],[0,3],[1,4]]`} output="true">
    Four edges for five nodes, all connected, no cycle.
  </Example>
  <Example input={`n = 5
edges = [[0,1],[1,2],[2,3],[1,3],[1,4]]`} output="false">
    Five edges for five nodes — one too many, and 1–2–3 closes a cycle.
  </Example>
  <Example input={`n = 4
edges = [[0,1],[2,3]]`} output="false">
    No cycle, but two separate pieces. A tree must be connected.
  </Example>
</Examples>

<Constraints>

- `1 <= n <= 2000`, `0 <= edges.length <= 5000`
- Edges are **undirected**; `[0,1]` and `[1,0]` never both appear
- No self-loops, no repeated edges

</Constraints>

</Statement>

<Signals>

- A tree is two conditions at once — **connected** and **acyclic** — and the third example exists to
  stop you checking only one.
- There is an arithmetic shortcut: a tree on `n` nodes has **exactly `n - 1` edges**. With that count
  confirmed, connected *implies* acyclic and vice versa, so only one of the two still needs checking.
- Adding an edge between two nodes already in the same component **creates a cycle**. That is precisely
  the question union-find answers in near-constant time.

</Signals>

<BruteForce>

Depth-first from node 0, tracking the parent to avoid walking straight back along the edge you came
from. Report `false` on revisiting a non-parent node, and `false` at the end if any node was unvisited.

**O(n + e) time, O(n) space.** This is a perfectly good solution — arguably the clearest one — and it
needs no extra structure. The bottleneck is not performance but generality: the parent trick breaks
with repeated edges, and the same question asked incrementally (edges arriving one at a time) cannot be
answered by re-running a traversal.

</BruteForce>

<Insight>

n − 1 edges and no cycle is already a tree, and a cycle is exactly an edge joining two nodes that were already connected.

</Insight>

<Approach>

1. **Count first.** A tree needs exactly `n - 1` edges; anything else is an immediate `false`. Too many
   forces a cycle, too few forces a disconnection.
2. Give every node its own component.
3. For each edge, find the roots of both endpoints.
4. If they are **already the same**, this edge closes a cycle — return `false`.
5. Otherwise union them.
6. Surviving every edge with exactly `n - 1` of them means connected and acyclic: a tree.

Step 1 is what makes step 6 sound. Without the count, passing all the union checks only proves
acyclicity — the third example has no cycle and is still not a tree.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def validTree(self, n: int, edges: list[list[int]]) -> bool:
        # O(n + e) time, O(n) space — DFS carrying the parent
        if len(edges) != n - 1:
            return False

        graph: dict[int, list[int]] = {node: [] for node in range(n)}
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        seen = {0}
        stack = [(0, -1)]                      # (node, the node we came from)

        while stack:
            node, parent = stack.pop()
            for neighbour in graph[node]:
                if neighbour == parent:
                    continue                    # not a cycle, just the edge back
                if neighbour in seen:
                    return False
                seen.add(neighbour)
                stack.append((neighbour, node))

        return len(seen) == n
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def validTree(self, n: int, edges: list[list[int]]) -> bool:
        # O(n * alpha(n)) time, O(n) space — union-find
        if len(edges) != n - 1:
            return False                        # a tree has exactly n - 1 edges

        parent = list(range(n))
        rank = [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]   # path compression, halving
                x = parent[x]
            return x

        for a, b in edges:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:
                return False                    # both ends already connected: a cycle

            if rank[root_a] < rank[root_b]:     # union by rank
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a
            rank[root_a] += rank[root_b]

        return True                             # n - 1 edges, no cycle: a tree
```

</Solution>

<Pitfalls>

- **Check the edge count.** Union-find alone proves only "no cycle". The third example — two disjoint
  edges — passes every union and is not a tree. One line, and it is the difference between the two
  halves of the definition.
- **Undirected DFS needs the parent, not just a visited set.** Every edge appears twice, so walking
  back to where you came from looks like a cycle. Passing the parent is the standard fix, and it fails
  if repeated edges were allowed — which the constraints rule out.
- With `n = 1` and no edges the answer is `true`: `0 == 1 - 1` holds, and a single node is a tree.
- **Union by rank plus path compression** is what makes `find` near-constant. Without either, a chain
  of unions degrades to `O(n)` per operation and the whole thing becomes quadratic.
- Compare **roots**, not the nodes themselves. `if a == b` tests labels, not components, and never
  fires.

</Pitfalls>

<FollowUps>

- *"Count the components instead."* — The next problem: the same union-find, returning how many
  distinct roots remain.
- *"Edges arrive one at a time."* — Union-find handles it directly; the DFS version would have to
  re-run from scratch after every edge. That is the real reason to know both.
- *"Directed edges."* — A different problem entirely: "valid tree" becomes "exactly one root, every
  other node with in-degree 1, and no cycle", and the parent trick no longer applies.

</FollowUps>
