<Statement>

A network of `n` nodes labelled `1` to `n` has directed edges `times[i] = (u, v, w)` — a signal takes
`w` time to travel from `u` to `v`. Sending a signal from node `k`, return the time until **all** nodes
have received it, or `-1` if some node never does.

<Examples>
  <Example input={`times = [[2,1,1],[2,3,1],[3,4,1]]
n = 4, k = 2`} output="2">
    Node 1 hears at time 1, node 3 at time 1, node 4 at time 2. The answer is the **last** arrival.
  </Example>
  <Example input={`times = [[1,2,1]]
n = 2, k = 1`} output="1">
    A single edge.
  </Example>
  <Example input={`times = [[1,2,1]]
n = 2, k = 2`} output="-1">
    Edges are **directed**. Node 1 is unreachable from node 2.
  </Example>
</Examples>

<Constraints>

- `1 <= k <= n <= 100` and `1 <= times.length <= 6000`
- `0 <= w <= 100` — weights are **non-negative**
- Edges are directed, with no duplicate pairs

</Constraints>

</Statement>

<Signals>

- Edges have **weights**, so breadth-first search no longer finds shortest paths — a route with more
  hops can be faster. That single fact is what moves this out of the Graphs category.
- Weights are **non-negative**, which is exactly the precondition Dijkstra needs. Say it out loud; with
  a negative edge the algorithm silently returns wrong answers.
- The question asks when *everyone* has heard, so the answer is the **maximum** over all shortest
  distances — not the minimum, and not a sum.

</Signals>

<BruteForce>

Bellman-Ford: relax every edge `n - 1` times.

**O(V · E) time** — 600 000 relaxations here, which passes comfortably. It is correct, it is simpler to
write, and it tolerates negative weights, which Dijkstra does not. The bottleneck is that it keeps
re-relaxing edges whose endpoints have not improved; a priority queue visits each node once, in the
order their distances are finalised.

</BruteForce>

<Insight>

Always expand the unvisited node with the smallest known distance — with non-negative weights, that distance can never improve later.

</Insight>

<Approach>

1. Build an adjacency list of `(neighbour, weight)`.
2. Push `(0, k)` onto a min-heap and keep a `visited` set.
3. Pop the smallest `(distance, node)`. If already visited, discard it — the heap holds stale entries.
4. Mark it visited; its distance is now final.
5. Push `(distance + w, neighbour)` for each outgoing edge.
6. When the heap empties, the answer is the largest distance recorded — or `-1` if fewer than `n` nodes
   were visited.

Step 3 is the part that is easy to leave out. Improving a node's distance pushes a second entry rather
than updating the first, so the heap accumulates outdated pairs and every pop has to be checked.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def networkDelayTime(self, times: list[list[int]], n: int, k: int) -> int:
        # O(V * E) time, O(V) space — Bellman-Ford
        distance = [float("inf")] * (n + 1)
        distance[k] = 0

        for _ in range(n - 1):                    # n - 1 rounds suffice
            changed = False
            for u, v, w in times:
                if distance[u] + w < distance[v]:
                    distance[v] = distance[u] + w
                    changed = True
            if not changed:
                break

        longest = max(distance[1:])
        return -1 if longest == float("inf") else int(longest)
```

</Solution>

<Solution variant="optimal">

```python
import heapq
from collections import defaultdict


class Solution:
    def networkDelayTime(self, times: list[list[int]], n: int, k: int) -> int:
        # O(E log V) time, O(V + E) space — Dijkstra
        graph: dict[int, list[tuple[int, int]]] = defaultdict(list)
        for u, v, w in times:
            graph[u].append((v, w))

        heap = [(0, k)]
        visited: set[int] = set()
        elapsed = 0

        while heap:
            distance, node = heapq.heappop(heap)
            if node in visited:
                continue                          # a stale entry: already finalised
            visited.add(node)
            elapsed = distance                    # pops come out in increasing order

            for neighbour, weight in graph[node]:
                if neighbour not in visited:
                    heapq.heappush(heap, (distance + weight, neighbour))

        return elapsed if len(visited) == n else -1
```

</Solution>

<Pitfalls>

- **Return the maximum, not the minimum or the sum.** The question is when the *last* node hears the
  signal. Because Dijkstra pops in increasing order, the final pop already holds it — but only if you
  keep the value rather than accumulating.
- **Skip already-visited nodes on pop.** A node can be pushed several times with different distances;
  without the check it is expanded repeatedly and the complexity degrades.
- **`-1` when some node is unreachable.** Comparing `len(visited)` against `n` is the check, and
  forgetting it returns a plausible number for a disconnected graph. Edges are directed, so this is not
  a rare case.
- Nodes are labelled `1..n`, so an array of size `n + 1` and a slice from index 1. Off-by-one here
  either crashes or silently includes a phantom node at distance infinity.
- Dijkstra is only valid because `w >= 0`. With a negative edge it can finalise a node too early —
  Bellman-Ford is the answer there, and knowing which precondition you are relying on is the point.

</Pitfalls>

<FollowUps>

- *"Negative weights."* — Bellman-Ford, at `O(V · E)`, and it also detects negative cycles by checking
  whether an `n`-th round still improves anything.
- *"The shortest path to one specific node."* — Stop as soon as that node is popped. The rest of the
  heap is irrelevant, and the early exit is free.
- *"Return the path, not the time."* — Store a predecessor per node when its distance is finalised, then
  walk backwards from the target.

</FollowUps>
