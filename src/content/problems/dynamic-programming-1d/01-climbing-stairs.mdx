<Statement>

A staircase has `n` steps. Each move climbs **1 or 2** steps. In how many distinct ways can you reach
the top?

<Examples>
  <Example input={`n = 2`} output="2">
    `1+1` and `2`.
  </Example>
  <Example input={`n = 3`} output="3">
    `1+1+1`, `1+2` and `2+1`. Order matters — these are three different climbs.
  </Example>
  <Example input={`n = 1`} output="1">
    One step, one way.
  </Example>
</Examples>

<Constraints>

- `1 <= n <= 45`

</Constraints>

</Statement>

<Signals>

- The **last** move was either a 1 or a 2, so every climb to step `n` extends a climb to `n-1` or to
  `n-2`. That sentence is the recurrence, and writing it down is the whole of dynamic programming.
- The two cases do not overlap — a climb ending in a 1-step is never the same as one ending in a
  2-step — so the counts **add** rather than needing any deduplication.
- `n <= 45` is a warning, not a comfort: the naive recursion branches twice per call, so `2^45` is
  where it lands without memory.

</Signals>

<BruteForce>

Recurse directly: `ways(n) = ways(n-1) + ways(n-2)`, with `ways(0) = ways(1) = 1`.

**O(2^n) time, O(n) stack.** It is the recurrence written out and it is correct. The bottleneck is that
`ways(n-2)` is computed once inside `ways(n-1)` and again directly, and that duplication compounds at
every level. At `n = 45` it is roughly `10^13` calls.

</BruteForce>

<Insight>

Every climb ends in a 1 or a 2, so the ways to reach a step are the ways to reach the two steps below it.

</Insight>

<Approach>

1. `ways(0) = 1` — one way to be at the bottom, doing nothing.
2. `ways(1) = 1`.
3. For each step from 2 upwards, `ways(i) = ways(i-1) + ways(i-2)`.
4. Only the last two values are ever read, so two variables suffice instead of an array.

That is the Fibonacci sequence, offset by one. Recognising it is satisfying but not the point — the
point is the shape: **define the state, find the recurrence, work upwards, then notice how little of
the table you actually need.**

</Approach>

<Solution variant="brute">

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # O(2^n) time, O(n) stack — the recurrence with nothing remembered
        def ways(step: int) -> int:
            if step <= 1:
                return 1
            return ways(step - 1) + ways(step - 2)

        return ways(n)
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # O(n) time, O(1) space — only the last two values are ever needed
        one_below, two_below = 1, 1          # ways(1), ways(0)

        for _ in range(2, n + 1):
            one_below, two_below = one_below + two_below, one_below

        return one_below
```

</Solution>

<Pitfalls>

- **`ways(0) = 1`, not 0.** There is exactly one way to climb nothing, and setting it to 0 shifts the
  whole sequence and makes every answer wrong by a term.
- Order matters. `1+2` and `2+1` are different climbs, which is why the counts add and why this is not
  a partition problem.
- The two-variable version reads more clearly with names than with `a, b`. The rolled-up assignment
  updates both at once — writing it as two statements needs a temporary, and forgetting it is a
  classic slip.
- `n = 1` must return 1. The loop never runs and `one_below` is already 1, so no special case is
  needed — but check it, because the initialisation is doing the work.
- Memoising the recursion is equally valid and `O(n)`; it just carries `O(n)` stack. At `n <= 45` both
  are fine, and saying which resource you are spending is the habit worth building here.

</Pitfalls>

<FollowUps>

- *"Steps of 1, 2 or 3."* — `ways(i) = ways(i-1) + ways(i-2) + ways(i-3)`. Three variables. The shape
  does not change at all, which is the point.
- *"Arbitrary allowed step sizes."* — Sum over each allowed size, which is exactly Coin Change with
  counting instead of minimising.
- *"n up to 10^18."* — Matrix exponentiation of the Fibonacci recurrence, in `O(log n)`. Worth knowing
  it exists; not worth reaching for at `n <= 45`.

</FollowUps>
