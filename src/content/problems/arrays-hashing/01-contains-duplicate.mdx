<Statement>

Given an integer array `nums`, return `true` if any value appears **at least twice**, and
`false` if every element is distinct.

<Examples>
  <Example input={`nums = [1, 2, 3, 1]`} output="true">
    The value 1 sits at index 0 and again at index 3.
  </Example>
  <Example input={`nums = [1, 2, 3, 4]`} output="false">
    Every element is distinct, so the scan runs to the end.
  </Example>
  <Example input={`nums = [1, 1, 1, 3, 3, 4, 3, 2, 4, 2]`} output="true">
    Several values repeat here; a single repetition is already enough for the answer.
  </Example>
</Examples>

<Constraints>

- `1 <= n <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

</Constraints>

</Statement>

<Signals>

- The question is *"have I seen this value before?"* — membership, not order. That is the hashing
  family, and the answer needs no arithmetic at all.
- `n` up to `10^5` puts the nested loop at `10^10` comparisons in the distinct case. That is the
  version you are expected to beat.
- Values run to `±10^9` while `n` is only `10^5`, so an array indexed by value is out. The set has to
  be a hash set.

</Signals>

<BruteForce>

Compare every pair: for each `i`, walk every `j > i` and test `nums[i] == nums[j]`.

Correct, and **O(n²) time, O(1) space**. The bottleneck is the inner loop: it answers *"is this value
somewhere else in the array?"* by scanning. That question is a lookup, and lookups belong in a set.

</BruteForce>

<Insight>

Carry the values you have already seen in a set — the first value that is already in it is the answer.

</Insight>

<Approach>

1. Start with an empty set `seen`.
2. Walk the array once.
3. If the current value is already in `seen`, return `true` immediately.
4. Otherwise add it and continue.
5. Surviving the loop means every element was distinct — return `false`.

Returning at the first repeat matters: on `[1, 1, 1, …]` the loop ends after two steps instead of
building a set of the whole array.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        # O(n^2) time, O(1) space
        for i in range(len(nums)):
            for j in range(i + 1, len(nums)):
                if nums[i] == nums[j]:
                    return True
        return False
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        # O(n) time, O(n) space
        seen: set[int] = set()

        for x in nums:
            if x in seen:
                return True
            seen.add(x)

        return False
```

</Solution>

<Pitfalls>

- `len(set(nums)) != len(nums)` is the same idea in one line and is a fine thing to say out loud —
  but it always builds the entire set, while the loop stops at the first repeat. Mention both and
  name the difference; that is what the interviewer is listening for.
- **The sorting alternative is not O(1) space in Python.** Sorting and comparing neighbours is a
  genuine `O(n log n)` answer with no hash map, but `sorted()` copies and `list.sort()` needs `O(n)`
  auxiliary memory in the worst case. Say "O(1) *besides the sort*", not "O(1)".
- Do not reach for a counting array. The values span `2 · 10^9` possible slots for at most `10^5`
  elements.

</Pitfalls>

<FollowUps>

- *"No extra memory at all."* — Sort in place and compare neighbours: `O(n log n)` time, and it
  destroys the original order. State that trade-off rather than presenting it as strictly better.
- *"Return the duplicate itself."* — Return `x` instead of `True`; nothing else changes.
- *"True only if a duplicate is within k indices."* — That is LC 219: hold a sliding window of the
  last `k` values in the set and drop the one leaving the window.

</FollowUps>
