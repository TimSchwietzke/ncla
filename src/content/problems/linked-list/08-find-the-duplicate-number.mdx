<Statement>

An array `nums` holds `n + 1` integers, each in the range `[1, n]`. Exactly one value is repeated.
Return it — **without modifying the array** and using only **constant extra space**.

<Examples>
  <Example input={`nums = [1, 3, 4, 2, 2]`} output="2">
    Five slots, values from 1 to 4, so something has to repeat — here the 2.
  </Example>
  <Example input={`nums = [3, 1, 3, 4, 2]`} output="3">
    The repeat need not be adjacent or in any particular place.
  </Example>
  <Example input={`nums = [3, 3, 3, 3, 3]`} output="3">
    The repeated value may appear more than twice.
  </Example>
</Examples>

<Constraints>

- `1 <= n <= 10^5` and `nums.length == n + 1`
- `1 <= nums[i] <= n`
- The array may **not** be modified, and only `O(1)` extra space may be used

</Constraints>

</Statement>

<Signals>

- The two restrictions do all the work. **No modification** rules out sorting and in-place marking;
  **`O(1)` space** rules out a set or a count array. What is left has to be arithmetic on the values
  themselves.
- Values live in `[1, n]` and indices in `[0, n]`, so `i → nums[i]` is a valid jump for every index.
  That turns the array into a **linked list**, walked without any pointers.
- Two different indices holding the same value means two arrows landing on one node — and a node with
  two arrows into it is exactly the entrance of a cycle.

</Signals>

<BruteForce>

For each value, scan the rest of the array for a second occurrence.

**O(n²) time, O(1) space.** It respects both restrictions and it is correct, which makes it the right
opening answer — a hash set would be `O(n)` time but breaks the space rule, so it is *worse* here
despite being faster. The bottleneck is that the scan learns nothing it can carry forward.

</BruteForce>

<Insight>

Reading `i → nums[i]` as a linked list makes the duplicated value the entrance of a cycle, because it is the one node two arrows point at.

</Insight>

<Approach>

1. Treat index `i` as a node whose successor is `nums[i]`. Start at index 0, which is outside the
   range `[1, n]` of values and therefore never a target — so the walk enters the cycle rather than
   starting inside it.
2. **Phase 1:** run `slow` one step and `fast` two until they meet. That proves a cycle exists and
   finds *a* node inside it.
3. **Phase 2:** reset `slow` to index 0, leave `fast` at the meeting point, and advance **both one
   step at a time**. Where they meet is the entrance of the cycle.
4. That entrance is the duplicated value.

Phase 2 is the part that looks like magic. The distance from the start to the entrance and the
distance from the meeting point to the entrance are congruent modulo the cycle length — so two
walkers at equal speed, starting from those two places, arrive together.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def findDuplicate(self, nums: list[int]) -> int:
        # O(n^2) time, O(1) space — obeys both restrictions
        for i in range(len(nums)):
            for j in range(i + 1, len(nums)):
                if nums[i] == nums[j]:
                    return nums[i]
        return -1
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def findDuplicate(self, nums: list[int]) -> int:
        # O(n) time, O(1) space — Floyd's algorithm on i -> nums[i]
        slow, fast = 0, 0
        while True:                       # phase 1: find a node inside the cycle
            slow = nums[slow]
            fast = nums[nums[fast]]
            if slow == fast:
                break

        slow2 = 0
        while slow != slow2:              # phase 2: walk both at one step to the entrance
            slow = nums[slow]
            slow2 = nums[slow2]

        return slow
```

</Solution>

<Pitfalls>

- **Phase 2 is not optional.** The meeting point of phase 1 is *some* node in the cycle, almost never
  the entrance. Returning it passes the occasional test by luck and fails the rest.
- **Both pointers move one step in phase 2.** Keeping `fast` at two steps finds a meeting point again,
  but not the entrance.
- **Start at index 0.** It works precisely because values are at least 1, so nothing ever points back
  at index 0 — the start is guaranteed to sit outside the cycle, which the argument requires.
- A hash set solves this in `O(n)` time and is *not* an acceptable answer here: the statement forbids
  the space. Say that explicitly rather than offering it as the optimal one.
- Marking visited values by negating `nums[abs(v)]` is the other classic trick, and it **modifies the
  array**, which is also forbidden. Both of the "obvious" fast answers are ruled out on purpose.

</Pitfalls>

<FollowUps>

- *"Prove the phase-2 step."* — Let `a` be the distance to the entrance and `b` the distance from the
  entrance to the meeting point, with cycle length `c`. Phase 1 gives `2(a + b) = a + b + kc`, so
  `a = kc - b`: walking `a` from the start and `a` from the meeting point both land on the entrance.
- *"If modification were allowed?"* — Sort and look for neighbours, `O(n log n)`; or negate
  `nums[abs(v)]` as a visited mark, `O(n)` time and `O(1)` space. Both are simpler and both are
  banned here.
- *"More than one duplicate?"* — Floyd's finds one cycle entrance, so it returns one value.
  Enumerating all of them needs the space the problem denies you.

</FollowUps>
