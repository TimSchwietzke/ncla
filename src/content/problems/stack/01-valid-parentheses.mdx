<Statement>

Given a string `s` of the characters `(`, `)`, `{`, `}`, `[` and `]`, decide whether it is **valid**:
every closing bracket must match the most recently opened one that is still unclosed, and nothing may
be left open at the end.

<Examples>
  <Example input={`s = "()[]{}"`} output="true">
    Three pairs, each closed immediately after it opens.
  </Example>
  <Example input={`s = "([])"`} output="true">
    Nesting is fine as long as the innermost bracket closes first.
  </Example>
  <Example input={`s = "([)]"`} output="false">
    Every bracket has a partner, but they interleave — the `[` is still open when the `)` arrives.
  </Example>
</Examples>

<Constraints>

- `1 <= s.length <= 10^4`
- `s` consists only of the characters `()[]{}`

</Constraints>

</Statement>

<Signals>

- "The most recently opened must close first" is the definition of **last in, first out**. That
  sentence is the data structure.
- `([)]` failing while `([])` succeeds proves that counting is not enough — the *order* matters, so a
  tally of how many of each bracket is open cannot work.
- Depth is unbounded within `n`, so whatever remembers the open brackets has to grow. `O(n)` space is
  the target, not a compromise.

</Signals>

<BruteForce>

Repeatedly scan the string for an adjacent matching pair — `()`, `[]` or `{}` — remove it, and start
over. The string is valid exactly when it collapses to nothing.

**O(n²) time, O(n) space.** It is correct and it is a fine way to *explain* the problem. The
bottleneck is the restart: each removal rescans everything, although the only thing that changed is
the immediate neighbourhood of the cut. A single pass can keep the same information if it remembers
what is still open.

</BruteForce>

<Insight>

A closing bracket only ever has to be checked against the single most recently opened one, so a stack is the whole answer.

</Insight>

<Approach>

1. Keep a map from each **closing** bracket to its opening partner.
2. Walk the string once.
3. If the character is not in the map, it is an opener — push it.
4. If it is a closer, the stack must be non-empty **and** its top must be the matching opener. Fail if
   either is untrue; otherwise pop.
5. At the end the stack must be empty. Anything left is an unclosed bracket.

The two failure modes in step 4 and step 5 are different strings: `")("` fails on the empty stack,
`"(("` fails on the final check. Both are needed and both are easy to leave out.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def isValid(self, s: str) -> bool:
        # O(n^2) time, O(n) space
        while True:
            shorter = s.replace("()", "").replace("[]", "").replace("{}", "")
            if shorter == s:
                return s == ""
            s = shorter
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def isValid(self, s: str) -> bool:
        # O(n) time, O(n) space
        closing = {")": "(", "]": "[", "}": "{"}
        stack: list[str] = []

        for ch in s:
            if ch not in closing:
                stack.append(ch)
                continue
            if not stack or stack[-1] != closing[ch]:
                return False
            stack.pop()

        return not stack          # anything left over was never closed
```

</Solution>

<Pitfalls>

- **Check that the stack is non-empty before reading its top.** `")("` crashes on `stack[-1]`
  otherwise, and it is the shortest failing input there is.
- **The final `return not stack` is not optional.** `"(("` never triggers a mismatch — it simply ends
  with two openers waiting. Returning `True` after the loop is the most common way this is written
  wrong.
- Counting brackets does not work, no matter how carefully. `([)]` has one of each and is invalid;
  order is the entire content of the problem.
- Keying the map by the **closing** bracket is what makes `ch not in closing` a clean test for "is
  this an opener". Keying it the other way round forces a second lookup.

</Pitfalls>

<FollowUps>

- *"Return the index of the first invalid character."* — Same loop, return `i` instead of `False`, and
  return the position of the leftover opener at the end via a stack of indices.
- *"The longest valid substring."* — LC 32: a stack of indices with a sentinel `-1` at the bottom, or
  a two-pass counter sweep. Much harder than it looks.
- *"How many brackets must be added to make it valid?"* — Track unmatched openers and unmatched
  closers separately; the answer is their sum, and no stack is needed at all.

</FollowUps>
