<Statement>

`n` cars sit at distinct positions on a one-lane road, each heading for `target`. Car `i` starts at
`position[i]` and drives at `speed[i]`. A car cannot overtake — when it catches a slower car it joins
it and continues at the slower speed. A group travelling together is a **fleet**, and a car that
catches a fleet exactly at `target` still counts as part of it.

Return how many fleets arrive at `target`.

<Examples>
  <Example input={`target = 12
position = [10, 8, 0, 5, 3]
speed = [2, 4, 1, 1, 3]`} output="3">
    10 and 8 meet exactly at 12; 5 and 3 meet at mile 6 and continue at speed 1; the car at 0 never
    catches anyone.
  </Example>
  <Example input={`target = 10
position = [3]
speed = [3]`} output="1">
    A single car is a fleet by itself.
  </Example>
  <Example input={`target = 10
position = [0, 4, 2]
speed = [2, 1, 3]`} output="1">
    The car at 4 is slowest and furthest ahead, so everything behind it piles up into one fleet.
  </Example>
</Examples>

<Constraints>

- `n == position.length == speed.length`, `1 <= n <= 10^5`
- `0 < target <= 10^6`, `0 <= position[i] < target`
- All positions are **distinct**
- `0 < speed[i] <= 10^6`

</Constraints>

</Statement>

<Signals>

- Cars cannot overtake, so the **order along the road never changes**. Whatever the answer is, it
  depends only on who is in front of whom — which means sorting by position is free information.
- Turn each car into the one number that matters: its **arrival time**, `(target - position) / speed`.
  Positions and speeds stop mattering the moment you have it.
- A car is absorbed exactly when it would arrive **no later** than the car ahead. That is a comparison
  against the nearest thing in front — the shape a stack answers.

</Signals>

<BruteForce>

Simulate. Advance time in small steps, move every car, merge any car that reaches the one ahead, and
count the groups that cross `target`.

**Slow and fragile.** Choosing a time step is guesswork: too coarse and cars pass through each other,
too fine and `10^5` cars over `10^6` miles is hopeless. The bottleneck is that the simulation computes
*where every car is at every moment*, when the only thing the answer depends on is **when each car
arrives**.

</BruteForce>

<Insight>

Replace each car by its arrival time, and a car joins the fleet ahead exactly when it would not arrive later than it.

</Insight>

<Approach>

1. Pair each position with its speed and sort **descending by position** — closest to the target
   first.
2. Walk that order and compute `time = (target - position) / speed` for each car.
3. Keep a stack of fleet arrival times. If the current car's time is **greater** than the time on top
   of the stack, it can never catch that fleet: push it, a new fleet.
4. Otherwise it catches up, so it is absorbed — do not push.
5. The answer is the number of entries left on the stack.

The stack never needs to be read below its top, so a single `slowest` variable does the same job in
`O(1)` space. Say that: it shows you understand *why* the stack works rather than reaching for one out
of habit.

</Approach>

<Solution variant="brute">

```python
class Solution:
    def carFleet(self, target: int, position: list[int], speed: list[int]) -> int:
        # O(n^2) time, O(n) space
        cars = sorted(zip(position, speed), reverse=True)
        times = [(target - p) / s for p, s in cars]

        fleets = 0
        for i in range(len(times)):
            # A car leads a fleet unless something ahead of it arrives no earlier.
            if all(times[i] > times[j] for j in range(i)):
                fleets += 1

        return fleets
```

</Solution>

<Solution variant="optimal">

```python
class Solution:
    def carFleet(self, target: int, position: list[int], speed: list[int]) -> int:
        # O(n log n) time for the sort, O(n) space
        cars = sorted(zip(position, speed), reverse=True)   # closest to target first
        stack: list[float] = []

        for p, s in cars:
            time = (target - p) / s
            if not stack or time > stack[-1]:
                stack.append(time)          # arrives later than the fleet ahead: its own fleet

        return len(stack)
```

</Solution>

<Pitfalls>

- **Use float division, not `//`.** Two cars whose arrival times are 3.5 and 3.2 are one fleet;
  truncated to 3 and 3 they still look like one, but 3.9 and 3.1 truncate to 3 and 3 as well while
  being genuinely different. Integer division merges fleets that never meet.
- **Sort descending by position.** Ascending order asks each car about the ones behind it, which
  cannot absorb it, and the answer comes out as the number of cars.
- The comparison is `time > stack[-1]`, strictly. A car arriving at *exactly* the same time is
  absorbed — the statement says catching a fleet at `target` still counts as joining it.
- The stack is never inspected below the top, so `fleets` plus one `slowest` float gives the same
  answer in `O(1)` space. Being able to see that is worth more than the stack itself.

</Pitfalls>

<FollowUps>

- *"Do it in `O(1)` extra space."* — Replace the stack with a single `slowest` variable: count a fleet
  whenever the current time exceeds it, then update it. The sort still dominates at `O(n log n)`.
- *"Which cars are in which fleet?"* — Same sweep; append to the current fleet's list instead of
  discarding an absorbed car.
- *"Two lanes, where overtaking is allowed."* — The ordering assumption collapses and with it the
  whole approach. Worth saying: this solution rests entirely on cars never passing each other.

</FollowUps>
